# Hallow Browser roadmap

## Done

| Version | What |
|---|---|
| 1.0 | A Chromium browser on Microsoft Edge WebView2 (Evergreen runtime; SDK Microsoft.Web.WebView2 1.0.4314.35: Core, Wpf, WebView2Loader x64), C# 5 / .NET 4.8, WPF chrome built in code. Tabs in a WindowChrome title bar (new / close / middle-click / drag reorder / context menu / Ctrl+Shift+T for the last 25 closed), address bar (Omni.Interpret: http/https/file as typed, localhost / IPs / [IPv6] -> http, known TLDs or 2-letter -> https, else search; javascript:/data: searched; DuckDuckGo default, Google / Bing / Brave Search), suggestions from typed addresses with a preconnect through the hidden pre-warmed WebView, back/forward/reload, downloads flyout (DownloadStarting handled), find bar (CoreWebView2.Find), zoom chip, print, fullscreen video + F11, NewWindowRequested -> new tab with the same CoreWebView2 (opener kept), Chrome's shortcuts, session restore (background tabs load on click), PreferredColorScheme dark/auto/light. Hallow console look: Theme.xaml (every chrome colour a resource, accent swapped from theme.json live). Hallow Shield 1.6 built in as a WebView2 browser extension (AreBrowserExtensionsEnabled + AddBrowserExtensionAsync; re-added when the version/folder changes; no way to remove it), Shield button -> popup.html?tab=<id> in a small owned window (tab id via chrome.tabs.query by URL), options page in a tab, network-only fallback from Shield's plain block rules via WebResourceRequested, Shield updates from its GitHub release (sha256) into LocalAppData\HallowBrowser\Shield. Hallow Keys over its native-host pipe protocol (session secret, match/fill/status), fills only after the key click + login click, origin pinned at the click and re-checked in the page (top frame only). Gaming-light mode (known game processes + Hub's playing list; TrySuspendAsync for quiet background tabs, BelowNormal priority for the app and all WebView2 processes, MemoryUsageTargetLevel Low, GAME MODE chip; tabs it slept wake after the game), tab sleeping (N minutes), soft RAM limiter (LRU suspend then discard), CPU limiter, pop-out video (topmost borderless window hosting the tab, biggest video fills it), Hallow quick panel (Guard score, Mixer, Clips save, Hub). Privacy: third-party cookies blocked via the profile preference cookie_controls_mode, enable_do_not_track, Sec-GPC + DNT on page requests and navigator.globalPrivacyControl, tracking prevention Balanced/Strict, password autosave / autofill off, clear browsing data now or on exit. Speed: environment created while the window is built, a pre-warmed hidden WebView for the next new tab (local new-tab page via a virtual host), multicore JIT profile, renderer-process-limit 8. Family pipe (ping, status, open [url], menu, invoke, quit), status.json (no addresses), --cmd, --snap, crash reports, GitHub updater (sha256), installer registering it as a selectable browser (never the default). Tests: unit tests; integration off-screen against local pages, a stand-in Keys and a fake game (Shield extension + fallback, cookies with a control run, GPC/DNT, Keys click-only and origin refusal, game mode, pop-out, find, zoom, downloads, family pipe, perf, session restore) |

## Later / known limits

| Idea | Why it isn't in 1.0 |
|---|---|
| Shield's "blocked on this page" number | `getMatchedRules` needs Shield's optional `declarativeNetRequestFeedback` permission; WebView2 has no extension permission prompt. Could be granted at load later |
| Shield's Hallow family bridge inside the browser | Needs native messaging, which WebView2 doesn't have. The browser could relay Shield's family messages itself |
| Sec-GPC on every sub-request | 1.0 adds it to page (document) requests only, to keep a per-request hook off the hot path; DNT is on every request (Chromium's own preference) and navigator.globalPrivacyControl is set |
| Pop-out over exclusive full-screen games | Nothing can draw over an exclusive full-screen game; it works over borderless / windowed games |
| More than one window | 1.0 is one window with tabs (Ctrl+N opens a tab) |
| Start-up compared with Edge | Not measured: it would have meant opening Edge on your screen |
