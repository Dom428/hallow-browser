| Idea | Why it isn't in 1.0 |
|---|---|
| ~~Shield's "blocked on this page" number~~ | Done in **1.4**: WebView2 still can't grant optional permissions (and `chrome.permissions.request` gets no answer there), so the browser loads its own copy of Shield with the permission required |
| ~~Shield's Hallow family bridge inside the browser~~ | Done in **1.4**: no native messaging in WebView2, so the browser relays Shield's own report into status.json itself |
| Sec-GPC on every sub-request | 1.0 adds it to page (document) requests only, to keep a per-request hook off the hot path; DNT is on every request (Chromium's own preference) and navigator.globalPrivacyControl is set |
| Pop-out over exclusive full-screen games | Nothing can draw over an exclusive full-screen game; it works over borderless / windowed games |
| ~~More than one window~~ | Done in **1.4** (Ctrl+N, tear-off, moving tabs between windows, private windows) |
| Shield's full blocking in private windows | WebView2 has no "allow in InPrivate" for extensions: they load into an InPrivate profile but don't run. 1.4 uses Shield's network-only fallback there (no cosmetic filtering, no per-site modes) |
| Chrome Web Store / extension updates | WebView2 has no store support; extensions are loaded unpacked and updated by loading the newer folder |
| Blocking cookies for one site | WebView2 has no per-site cookie setting; 1.4 can delete a site's cookies (third-party cookies stay blocked everywhere) |
| Secure DNS without a restart | The engine reads Local State's DNS-over-HTTPS setting when it starts; there's no API to change it while it runs |
| Start-up compared with Edge | Not measured: it would have meant opening Edge on your screen |
| A bandwidth cap for the whole browser | WebView2 has no such API; 1.1's cap is DevTools network emulation per tab and panel (each gets the full cap; engine traffic outside pages isn't covered) |
| Live notifications without scraping | Twitch's and YouTube's official APIs need developer keys / sign-in; 1.1 reads the public channel pages instead, which can break when the sites change |
| Workspaces that keep their pages running | 1.2 closes the pages of the workspace you leave (like a restart) to save memory; keeping every workspace's pages alive would cost the memory of all of them |
| Pictures in reader mode | The reader view is drawn by the browser from text blocks; fetching pictures outside the page engine would bypass Shield and the profile, so 1.2 shows their captions |
| Showing as "Hallow Browser" in Windows' media controls | WebView2 registers playing pages with Windows' media session itself, under the engine's name (msedgewebview2.exe); there's no API to rename it |
| A real per-download speed limit | WebView2 has none, and DevTools network emulation misses link downloads; 1.5 holds the limit by pausing and resuming each download |
| Sidebar panels with their own separate sign-ins | Panels share the browser's profile on purpose (signed in like your tabs); 1.6's profiles give a second account per site as a whole profile |
| Spell check in several languages at once / any language | WebView2 ignores Chromium's `spellcheck.dictionaries` (measured in 1.6) and checks with Windows' spell checker in the engine's language - one language, engine-wide, only those Windows has spelling for |
| "Add to dictionary" at once | WebView2 has no API for it; 1.6 writes the profile's dictionary file, which the engine reads when it starts |
| A startup boost that keeps the engine warm | WebView2 ends its browser process with the last page; keeping one hidden page alive would cost ~100+ MB, so 1.6's boost keeps only the browser's own (trimmed) process |
| Casting to a Chromecast / TV | WebView2 has Chromium's Presentation API but no Media Router behind it (measured in 1.7: no screens are ever found, no Cast dialog), and a DLNA / Cast stack of our own would be a project of its own; 1.7 opens the tab in Microsoft Edge, which can cast |
