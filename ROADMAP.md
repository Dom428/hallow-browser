## Later / known limits

| Idea | Why it isn't in 1.0 |
|---|---|
| Shield's "blocked on this page" number | `getMatchedRules` needs Shield's optional `declarativeNetRequestFeedback` permission; WebView2 has no extension permission prompt. Could be granted at load later |
| Shield's Hallow family bridge inside the browser | Needs native messaging, which WebView2 doesn't have. The browser could relay Shield's family messages itself |
| Sec-GPC on every sub-request | 1.0 adds it to page (document) requests only, to keep a per-request hook off the hot path; DNT is on every request (Chromium's own preference) and navigator.globalPrivacyControl is set |
| Pop-out over exclusive full-screen games | Nothing can draw over an exclusive full-screen game; it works over borderless / windowed games |
| More than one window | 1.0 is one window with tabs (Ctrl+N opens a tab) |
| Start-up compared with Edge | Not measured: it would have meant opening Edge on your screen |
| A bandwidth cap for the whole browser | WebView2 has no such API; 1.1's cap is DevTools network emulation per tab and panel (each gets the full cap; engine traffic outside pages isn't covered) |
| Live notifications without scraping | Twitch's and YouTube's official APIs need developer keys / sign-in; 1.1 reads the public channel pages instead, which can break when the sites change |
| Workspaces that keep their pages running | 1.2 closes the pages of the workspace you leave (like a restart) to save memory; keeping every workspace's pages alive would cost the memory of all of them |
| Pictures in reader mode | The reader view is drawn by the browser from text blocks; fetching pictures outside the page engine would bypass Shield and the profile, so 1.2 shows their captions |
| Sidebar panels with their own separate sign-ins | Panels share the browser's profile on purpose (signed in like your tabs); a second account per site would need a second WebView2 profile |
